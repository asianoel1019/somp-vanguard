系統 REST API 規格技術總表

sys-op-manager 支援全功能 RESTful API，涵蓋伺服器 CMDB、Scout 遙測、IPAM 網段拓撲、Nutanix 虛擬化、Kubernetes 容器管理、資料庫監控、Web Remote 遠端桌面閘道與運維自動化。本文檔覆蓋全系統 42 個路由模組、285+ 端點之詳細欄位、認證規範與完整請求/回應範例。

🔑 API 認證機制與 Token 類型分類 (Authentication & Token Types)

本系統提供多層次安全認證機制，支援使用者 JWT Token、Open API Key (開放介接) 與 Scout Agent Key 三種模式：

Token 類型 Request Header / 參數 適用端點範圍 取得方式與說明
1. JWT Bearer Token Authorization: Bearer <JWT> 全系統 200+ 核心 API
(如 /api/server-list, /api/ipam/*, /api/database/*, /api/kubernetes/* 等)		 透過 POST /api/auth/login 輸入帳密驗證成功後簽發。前端 UI 及後續自動化運維腳本一律使用此 Token 存取。
2. Open API Key Authorization: Bearer <KEY>
或 X-API-Key: <KEY>
或 ?apiKey=<KEY>		 Open Scout & CMDB 開放 API
(/api/v1/open/* 系列，包含 /api/v1/open/server-list, /api/v1/open/metrics/* 等 11 個端點)		 免帳密登入，專供外部監控系統（Grafana、Prometheus、Zabbix）或第三方系統長期整合。於後台 Agent Manager > API Keys 建立並啟用。
3. Scout Agent Key Body 帶 apiKey 或 Header Scout 遙測收集端點
(/api/monitor/report, /api/monitor/event)		 安裝於各主機之 Scout Agent (Windows / Linux 服務) 定期回傳即時 CPU/RAM/Disk 遙測指標使用。
4. 公開端點 (Public) 無需攜帶 Token POST /api/auth/login
GET /api/health
GET /api/inventory/download-scout-*		 登入入口、健康檢查與 Agent 安裝腳本下載。

GET/api/environments/unmapped
（SuperAdmin）列出各來源中無法對應到任何環境的已儲存值：{ consumers: [{ key, consumer, readOnly, total, values: [{ value, count }], error? }] }。key 與 usage 相同（cmdb、cmdb_meta、ipam_subnets、ipam_ips、ssl、db_clusters、db_requests、k8s、prometheus_name）；prometheus_name 為唯讀（標籤值不是環境名稱者，含 ID）。空值以 "" 表示。

（SuperAdmin）body：{ consumer, value, envId }。將該來源中所有帶有此未對應值（不分大小寫）的資料指定為 envId（同時寫入正式名稱，原始文字保留在 envRaw / environmentRaw / envNameRaw），回 { success, count, related? } 並寫入稽核。cmdb 與 cmdb_meta 互相連動：套用其中一個時，同一批 IP 在另一邊仍未對應的資料也會一併指定（related 回報筆數），避免之後的同步把舊值帶回。CMDB 大量資料以單一交易、每 500 筆一批更新。名稱 Unassigned、(empty) 為保留字，不可作為環境名稱。未知 consumer / envId 回 400；prometheus_name 回 400（不自動改寫）。
GET/api/environments/:id/usage
（SuperAdmin）查詢環境被引用的情形，回傳 { id, name, total, items: [{ consumer, count, keyedBy: "id"|"name" }] }。keyedBy: id 為以環境 ID 連結：Scout 監控、API Key、告警規則綁定、維護時段、CMDB envId、Server List metadata envId、Prometheus zone=ID，以及自 v1.7.5 起的 IPAM 子網路 / IP（ipam_subnets、ipam_ips）、SSL（ssl）、DB Inventory / 申請單（db_clusters、db_requests）、Kubernetes（k8s）——這些項目的計數另含尚未轉換、以名稱或代碼（不分大小寫）比對的舊資料。keyedBy: name 僅剩 CMDB / Server List metadata 中沒有有效 envId 的舊資料（cmdb_name、cmdb_meta_name，以名稱或代碼比對）與 Prometheus 標籤 zone/env/environment（prometheus_name）。刪除保護同樣依此計算。

PUT/api/environments/:id
