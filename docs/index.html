建立自動化排程與自癒

系統於 10/9 正式更新至 1.7 版，重大更新涵蓋遠端桌面閘道、底層多資料庫架構重構、Prometheus SD、ELK 生命週期與高可用容錯強化。

v1.7.7 安全修正 SECURITY
  • 安全修正：Web RDP 不再自動帶入 AD 管理員密碼：帳號預設為目前登入者，密碼一律需自行輸入；先前在帳號等於 AD_ADMIN_USER 時會自動帶入 AD_ADMIN_PWD，等於不需知道密碼即可以 AD 管理員身分登入 Windows 主機，已移除。
  • 安全修正：Remote Command：目標主機只接受 IPv4 / 主機名稱（修正可在 IP 欄夾帶 PowerShell 指令、於 SOMP 主機上執行的命令注入，Server Check 的 OS 偵測一併修正）；Windows 可輸入自己的 Windows 密碼以 網域\登入者 執行，個人帳號連線失敗或未輸入時改用 Settings 服務帳號（結果標示使用的帳號，指令最多執行一次），不再讀取專案根目錄 config.json 的明文密碼，帳密改經 stdin 傳遞、不寫入暫存檔；指令庫新增 / 刪除改需 Operator 以上並寫入稽核紀錄（修正 Viewer 可修改、Runbook 共用的指令庫），並修正刪除自訂指令時畫面錯誤。
  • 安全修正：Network Device SNMP 查詢：SNMP 查詢原本會使用前端傳入的 IP（Viewer 也可呼叫），可藉此讓系統把設備的 community / v3 帳號送到任意主機；改為一律使用機櫃中儲存的設備 IP。新增每台設備的「啟用 SNMP 查詢」開關，停用時完全不查詢；未設定過的設備預設停用，不再以 public 查詢。
  • 安全修正：SSL Manager：上傳憑證檔時，檔案類型與內容原本直接組進 PowerShell 腳本（可在 SOMP 主機上執行任意指令），改為 PEM / DER 由 Node 解析、PFX 以固定腳本經 stdin 傳入；清單不再回傳加密的私鑰 / 檔案；檢視私鑰改為僅限 SuperAdmin 並記入稽核紀錄。
v1.7.7 資料正確性與穩定性 MAJOR FIX
  • 修正：Data Center 可能整座機房被誤刪：原本儲存機房時會把整份清單送回覆蓋，畫面資料過舊時會刪除別人剛新增的機房（連同機櫃、設備、IPAM 的 IP 與 SNMP 設定）。改為逐筆新增 / 修改；刪除需 SuperAdmin 並輸入機房名稱確認，刪除後立即生效（修正原本刪除時回 500、機櫃資料未刪除的問題）。機櫃儲存加上版本檢查，別人已修改時拒絕並自動重新載入，不再覆蓋他人設備或誤釋放 IP；儲存前檢查 U 位重疊、超出高度、跨越 Split 分界與重複設備 ID。
  • 修正：Data Center 權限與備品庫存：機房、機櫃、硬體問題、合約的寫入 API 補上 Operator 以上的角色檢查（原本 Viewer 可直接呼叫 API 修改甚至刪除）；Network Device 的設備更新只接受機櫃資料。備品數量統一為 quantity 並由伺服器加減（修正報修選用備品時其實沒有扣庫存的問題），出庫超過庫存會拒絕；報修使用備品同一次選用只扣一次，庫存不足時報修不儲存。
  • 修正：IPAM 資料被覆蓋或清除：編輯網段名稱時會用畫面上的舊資料覆蓋整段 IP 的使用狀態，已改為只修改網段欄位；DNS 同步只清除確定抓取成功區域的 FQDN（原本部分抓取時會清空其他區域）；網頁與背景服務同時寫入 IPAM 時不再互相覆蓋；修正批次更新網段一律回 404 的問題。
  • 修正：SSL Manager 掃描與告警：只存檔案的憑證每天被誤探測、誤發告警且到期日被清掉的問題已修正；掃描結果改為合併寫回，不再覆蓋掃描期間新增 / 刪除的資料；新增「已過期」與「不受信任」顯示；告警改為只在狀態改變時發送；全部檢查改為背景平行執行；新增編輯功能與主機 / Port 驗證。
  • 修正：排程任務被執行兩次：在畫面新增或編輯排程任務（以及 Prometheus 健康檢查設定）後，網頁服務會另外啟動一個排程引擎，任務會被執行兩次直到重啟；已改為只由背景服務執行。
  • 統一資料存取：網頁服務與背景服務都會寫入的資料（CMDB 補充資料、排程、Prometheus 目標、Webhooks、RBAC 等）改為資料庫鎖定寫入，不再互相覆蓋；排程 / CMDB / DNS / Workflow 紀錄改存資料表並依 RETENTION_*_DAYS 自動清除（升級時自動搬移，舊資料保留）；新增寫入追蹤開關 DOC_WRITE_TRACE 與重複舊 key 清理工具 Cleanup_Doc_Aliases.bat（預設只產生報告）。
v1.7.7 功能改善 IMPROVEMENT
  • Network Device 修正：SNMP v2c 設定實際以 v1 查詢的問題已修正（新增 v1 選項）；設備清單與查詢不再直接讀取本機 SQLite（改用 PostgreSQL / MSSQL / MariaDB 時不會再整頁錯誤）；修改設備 IP 時會釋放舊 IP；刪除設備會一併刪除 SNMP 設定；新增設備與 SNMP 設定加上完整驗證，錯誤顯示實際原因。
  • IPAM 改善：CIDR 正規化並拒絕重複 / 重疊網段，新網段限 /20～/30，舊大網段同步時自動補上 IP；自動同步改為最精確網段比對，公網 IP 不再自動建立網段；「下一個可用 IP」跳過閘道與保留範圍並保留 10 分鐘；系統自動登記的 IP 手動修改需 SuperAdmin 確認；刪除含使用中 IP 的網段需 SuperAdmin 並輸入 CIDR；單一 IP 欄位驗證；網段清單改為只載入摘要，點開才載入 IP。
  • Topology Map 改版：修正機櫃背面設備未畫出、雙向連線畫成兩條而同一對設備的多條線只剩一條、同名設備亂接、跨機房設備被當成找不到等問題；連線改為無箭頭並標示兩端埠號（P1 ↔ P3）。新增隱藏未接線設備、網路 / 電源圖層與類型篩選、搜尋定位、保留拖曳位置與重新排版、重新整理與錯誤提示，以及手動觸發的即時埠狀態（只查已啟用 SNMP 的設備）。
  • Remote Command 穩定性：Linux 指令加上 120 秒執行逾時（不會再因 tail -f 等指令永久卡住）、每台輸出上限 512 KB；新增「停止」按鈕，關閉頁面也會停止派送尚未開始的主機；一次最多 200 台、重複主機自動合併、格式錯誤的請求回 400；開始與結束各寫一筆稽核紀錄。
  • 匯入檔依 OS 產生：依 CMDB 的 OS 產生 CPU / Memory / Disk 測試：Linux 維持 SNMP（net-snmp OID）；Windows 改用 PerfCounter（% Processor Time）、Memory（WMI）、DriveSpace（所有本機磁碟，剩餘 < 15%），與現行 HostMonitor 設定一致。CMDB 未填 OS 的主機只產生 Ping，其 CPU / Memory / Disk 會略過並列在檔案最後。比對結果顯示 OS 標籤，CSV 多一欄 OS。

  • 行為變更：功能開關同時管制 API（也影響非 SuperAdmin）：Remote Command、Server Check、Nutanix、Prometheus Target、Redis Control、SOP Runbook、Task Scheduler、SFTP Manager、Network Device、Live Event Viewer、Log Settings 新增 API 功能檢查。所屬群組未開啟這些功能的使用者（任何角色）將無法再呼叫其 API（403），畫面也不再顯示；共用 API（Web Remote、SNMP 設定 / 輪詢、Settings 的 Run Scan Now 與 SFTP 測試連線）具備任一相關功能即可。Network Device 設備管理改需 networkDevice（原為 dataCenter）；Live Event Viewer / Log Settings 改依各自功能，不再需要 monitorScout。另外 Data Center（/api/rack）、指令庫、ELK SIEM、SIEM Analytics、On-Demand Forensics、Webhooks、AI Service 的 API 也依呼叫畫面的功能檢查（未新增功能鍵）。所有使用者的側邊欄改依完整功能清單顯示（未開啟的 Scout Monitor、Alerts、Agents、NAS、HostMonitor Checker 等畫面會隱藏）。升級前請確認一般使用者的 AD Mapping 已勾選其需要的功能。

系統架構、登入安全與 RBAC 角色權限

SOMP Vanguard 專為 Windows Server 2016+ 高安全營運環境設計。系統採用雙軌身份驗證機制，並於底層透過 AES-256-CBC 強制加密權限設定檔，具備高度容錯與防篡改能力。

雙軌登入架構說明

1. 本地管理員 (Local Admin)：帳號 admin@local，密碼於環境變數 LOCAL_ADMIN_PWD 加密保存。用於系統初始化、AD 離線緊急排錯。
2. AD 網域驗證 (Active Directory)：支援 username@yourdomain.com，後台可限制僅允許指定 Organizational Unit (OU) 內的成員登入，並依 AD 群組動態對應系統角色。

🛡️ 全模組角色權限控管矩陣 (RBAC Matrix)

Chapter 02

伺服器維運與資產管理 (Server Operation)

Server Operation 是 SOMP Vanguard 最龐大且核心的運維子系統，整合簡化版配置管理庫 (Simplified CMDB)、全網段資產自動盤點、遠端指令庫中樞、原生本地時間輪排程引擎、視覺化 DAG 工作流程、多主機健康巡檢、Windows 遠端無人值守部署以及 Nutanix Prism 超融合管理。

🖥️ 2.1 Server List (Simplified CMDB 核心資料庫)

作為全系統的資產唯一事實來源 (Single Source of Truth)，自動關聯 Scout Agent 即時遙測、Prometheus Targets、IPAM 網段以及 Data Center Server Rack 機櫃空間。

  • 雙模式切換瀏覽：
    • Matrix Card View (卡片矩陣視圖)：以視覺化卡片呈現主機在線健康狀態、OS 圖示、即時 CPU/RAM 負載條與主要 IP。
    • Table View (詳細表格視圖)：提供全欄位即時多欄排序、多關鍵字過濾、批次操作與硬體漂移警示器。
  • 360° CMDB 側邊抽屜 (Drawer)：點擊任一主機即可展開右側抽屜，集中維護：主機名稱、OS 類型、主機序號 (SN)、iLO / iDRAC 管理 IP、CVM IP、機房位置 (Data Center / Rack / U 數)、群組標籤 (Tags) 與維運備註。
  • Dual-NIC / VIP 虛擬 IP 關聯：支援單一主機綁定次要 IP (VIP, Management IP, iLO IP)，並支援一鍵 Unlink 解除綁定。
  • 全域自動同步 (Global Auto-Sync)：於 Edit Mode 點擊 Global Auto-Sync，系統將平行自動探測：
    1. IPAM 線上子網路 Active IP。
    2. Prometheus 作用中 Targets 與標籤。
    3. Server Rack 機櫃 Compute 資源（包含獨立 Server、Nutanix 節點、Blade Chassis 刀鋒節點之 SN 與機櫃槽位）。

⚠️ 2.2 硬體規格漂移偵測與一鍵校準 (Hardware Drift)

當虛擬化環境動態擴容（如 vSphere 或 Nutanix 熱插拔增加 CPU 核心或 RAM），或實體主機更換硬體零件時，CMDB 歷史規格將與即時遙測產生不一致。

漂移告警與一鍵校準流程

1. 自動比對：系統自動比對 CMDB 記錄規格與 Live Agent / Prometheus 即時採集規格。
2. 告警呈現：不一致時在卡片與表格上高亮 ⚠️ Drift Detected 警示標籤。
3. 差異對照表：展開 360° CMDB 抽屜檢視 CPU Cores (CMDB vs Live) 與 Memory GB (CMDB vs Live) 差異。
4. 一鍵校準：點擊 「Sync Specs from Live Agent」 按鈕，系統立即將當前即時硬體規格校準回 CMDB，自動消除告警並寫入審計日誌。

🔍 2.3 Server Inventory (伺服器資產盤點與時區合規)

  • 多網段並行掃描：支援輸入多組 CIDR 網段（例如 192.0.2.0/24, 198.51.100.0/24），平行發起 ICMP、WinRM 與 SSH 探測。
  • 深層規格採集：自動解析作業系統發行版、Kernel 核心版本、CPU 型號/核數、記憶體插槽使用量、磁碟分區容量與開機時間 (Uptime)。
  • 時區合規性檢查 (Timezone Compliance Check)：依據主機回傳之 UTC Offset 與系統標準時區進行比對，偵測時鐘漂移或時區設定錯誤。
  • 自動化 HTML 郵件報表：支援一鍵產出格式精美的盤點報告，並經由內建 Mail Relay 定時或手動發送至維運人員信箱。

⌨️ 2.4 Remote Command (遠端指令庫與串流執行中樞)

支援在單一介面中對多台 Windows 與 Linux 主機執行遠端命令，具備高安全性與實時回饋能力：

  • 雙軌執行引擎：Windows 主機透過 WinRM / WMI 執行原生 PowerShell 腳本；Linux 主機透過 SSH 密鑰連線執行 Bash 腳本。
  • 指令庫 (Command Library / Snippets)：預置常用系統維護、服務重啟、磁碟快取清理、網路診斷與日誌收集指令模版。
  • 執行逾時保護 (Timeout Control)：可自訂指令執行逾時秒數，防止死鎖或長時間卡住。
  • 即時 NDJSON 串流輸出：秒級在終端視窗呈現遠端即時 Output，支援隨時中斷終止。
  • 資安審計追蹤：所有執行的指令、操作人員、目標主機 IP、執行時間與 Exit Code 均完整寫入安全稽核日誌。

⏱️ 2.5 Task Scheduler (原生時間輪任務排程中心)

原生本地時間輪詢引擎架構規範

後端排程引擎嚴格採用 「原生本地時間輪詢引擎」 執行，以 Windows OS 本地時間（Date 物件）配合 setInterval 進行輪詢比對。徹底杜絕了第三方 Cron 套件在 Windows Server 上因 UTC 跨日時差或夏令時計算錯誤導致的任務漏跑或重複觸發問題。

支援 Local PowerShell、Remote SSH、Remote WinRM 與智慧 OS 自動路由四種執行管道，滿足混合雲跨平台維運需求。

📋 2.6 Workflow Editor (視覺化 DAG 工作流程設計器)

提供直觀的 DAG (有向無環圖) 畫布，維運人員可將多個獨立維運步驟（SSH 節點、PowerShell 節點、HTTP API 節點、Delay 延時、Branch 條件判斷）串聯為全自動化管線，支援變數傳遞與失敗自動重試。

🔍 2.7 Server Check (跨主機批次健康巡檢與多埠連線診斷)

針對大型機房每日晨檢或重大維護前後的全面健康確認，提供高速平行多埠診斷能力：

  • 多協定平行探測：同步檢測 ICMP Ping 延遲、RDP (Port 3389)、WinRM (Port 5985/5986)、SSH (Port 22) 與自訂業務埠 (如 80, 443, 8080, 1433)。
  • 主機即時資源速查：巡檢過程中平行抓取主機 CPU 負載、實體記憶體可用率與 C: / Root 磁碟可用空間。
  • 批次篩選與異常匯出：支援一鍵篩選出所有連線超時、埠關閉或資源告急的主機，並可將巡檢報表匯出為標準 CSV / Excel 文件供交接使用。

🚀 2.8 Server Provision (遠端軟體部署中心：背景工作、預檢與歷史)

對已存在的 Windows / Linux 主機，依「業務單位 (BU) 範本」從 NAS 軟體庫遠端部署軟體（Windows 透過 WinRM、Linux 透過 SSH）。部署以背景工作 (Job) 執行，關閉瀏覽器不會中斷；進度、結果與記錄會保存於 Scout 資料庫，可隨時回頭查詢。

  • 目標選擇器 (Target Picker)：可搜尋 CMDB / Server Inventory 的主機（IP 或主機名稱）後多選，也可手動輸入 IP。
  • 已知目標規則 (Known-target rule)：為避免把已儲存的憑證送到任意 IP，只有「已知」的主機可以部署。已知 = 存在於 CMDB（且未被刪除），或存在於 Server Inventory（掃描探索到的 IP 也算已知，所以被盤點掃描過的網段內所有已記錄的 IP 皆視為已知）。未知 IP 會被拒絕（HTTP 400 並列出清單）。僅 SuperAdmin 可勾選「Allow unknown targets」覆寫，此動作會寫入稽核紀錄並記錄在工作內容中。
  • 預檢 (Pre-check)：按下 Pre-check 唯讀檢查每台主機：已知目標、連線埠（WinRM 5985 / SSH 22，1.5 秒）、登入驗證、資料碟 X: 剩餘空間 （預設至少 5 GB；X: 不存在視為不通過）、已安裝套件（資訊列，不影響通過與否）、NAS 路徑（整批只檢查一次）、是否已有其他工作正在處理該 IP。預檢不會安裝或變更任何東西，結果不會儲存。 Install 按鈕不會被鎖住，但預檢失敗或未執行時會出現警告。Linux 預檢首次連線時會釘選 SSH 主機指紋 (TOFU：首次信任)，之後指紋改變會被拒絕。
  • 背景工作與平行度：按下 Execute 立即建立工作並回傳工作編號。同時處理的主機數有上限（PROVISION_HOST_CONCURRENCY，預設 4，最大 10，同一個執行程序內所有工作合計）。 同一 IP 若已在另一個排隊 / 執行中的工作，該主機會被標示為 skipped（附上佔用它的工作編號）。
  • 由哪個程序執行 (Runner)：工作優先交給背景 Worker 執行（Web 只寫入資料庫並以 IPC 傳送工作編號，密碼不經過 IPC 也不會儲存，Worker 自行從設定讀取憑證）。 Worker 未啟動、傳送失敗或 5 秒內未回應時，改由 Web 自行執行（後援）。工作檢視會顯示「runs in: Background worker」或「Web server (fallback)」。 每個工作在資料庫中以單一原子操作認領，同一工作永遠只會在一個程序中執行。
    • 執行帳號（行為變更）：Windows 安裝以 Settings 的服務帳號 AD_ADMIN_USER / AD_ADMIN_PWD 執行（與 Server Inventory 掃描、部署 Agent 使用同一個預設憑證來源；未含網域的帳號會加上 ALLOWED_AD_DOMAIN），不再以登入者本人的帳密執行；Linux 以 LINUX_ADMIN_* 執行。 觸發的使用者記錄在工作的「Triggered by」、SOMP 稽核紀錄與安裝歷史；工作檢視另顯示「Run as: 服務帳號」（只顯示帳號名稱）。目標主機上的 Windows 事件記錄會看到服務帳號，而非觸發者。
    • 必須設定服務帳號：AD_ADMIN_USER / AD_ADMIN_PWD 未設定或無法解密時，Execute、Pre-check 與 Retry failed hosts 直接回 400「Server Provision requires the service account in Settings (AD_ADMIN_USER / AD_ADMIN_PWD)」，不會改用登入者密碼。
    • 每個執行程序自行從設定讀取憑證，因此所有工作都可交給 Worker，也都可在重啟後續跑。
    • 平行度上限在每個執行程序各自計算；正常情況工作都在 Worker，等同全域上限。若部分工作在 Web 後援執行，Web 與 Worker 各有一組同樣大小的名額（最多為設定值的兩倍）。
  • 工作檢視：每台主機一列，顯示狀態、各套件結束代碼 (exit code)、是否需要重新開機，並可展開記錄；執行中每 2 秒更新（分頁隱藏時暫停）。 記錄與較長的套件訊息僅 Operator / SuperAdmin 可見，Viewer 看到「Log visible to Operators only」。
  • 取消 (Cancel)：取消後不會再啟動新的主機或套件，排隊中的主機標示為 cancelled。已經在執行的 Windows 主機不會被中斷 （每台主機是一支完整的 PowerShell 腳本，會跑完其剩餘套件）；Linux 則會在目前套件結束後停止。 取消會在資料庫寫入取消旗標並通知執行程序；執行程序在每台主機 / 每個套件開始前與每 15 秒都會檢查旗標，所以即使 IPC 中斷也一定生效。
  • 歷史 (History) 與重試失敗主機 (Retry failed hosts)：History 分頁分頁列出過去的工作，可開啟查看。重試會建立一個新工作，只包含 failed / interrupted / skipped 的主機，沿用原本的範本與選項； 重新檢查目標是否仍為已知，不會繼承 SuperAdmin 覆寫，若有未知主機會被拒絕並列出，SuperAdmin 可明確按「Retry allowing unknown targets」。
  • 服務 / Worker 重啟後續跑 (Resume)：執行中的程序每 15 秒更新心跳。執行程序結束（服務重啟、Worker 異常結束後 5 秒自動重啟）或心跳超過 60 秒未更新時，由接手的程序處理該工作：
    • 尚未開始的主機 (queued)：自動續跑一次，沿用原本的範本與選項、重新讀取憑證，並重新檢查目標是否仍為已知主機及 IP 是否被其他工作佔用（不符者標示為 skipped 並附原因）。工作顯示「Resumed after restart」標記與備註，Telegram 完成摘要也會註明。
    • 執行到一半的主機 (running)：標示為 interrupted，不會自動重跑（目標主機可能安裝到一半，請先確認後用 Retry failed hosts）。
    • 已要求取消的工作：直接結束為 cancelled，不續跑。已續跑過一次的工作再次中斷時，剩餘主機標示為 interrupted（避免重啟迴圈）。
    • 續跑時以當下 Settings 的服務帳號執行（升級前建立、原本以登入者帳密執行的工作也一樣）；服務帳號已不存在或無法解密時，剩餘主機標示為 interrupted 並附原因。
    • Worker 的工作由 Worker 啟動時接手；Worker 異常結束時由 Web 立即接手並在 Web 續跑。Web 的工作（含升級前留下的舊工作）由 Web 啟動時接手。同一工作只會被一個程序接手。
    若某工作卡在執行中而執行程序已不存在，Operator 可按 Cancel 將其標示為 interrupted 並釋放 IP 鎖。
  • 重新開機規則：勾選 Reboot 時，只有「該主機所有套件都成功」且「至少有一個套件實際安裝」才會重新開機；任一套件失敗或全部被略過則略過重開機。結束代碼 3010 / 1641 視為成功但需要重新開機。
  • 資料碟 X:：Server Provision 不再有 Disk Setup（不再格式化磁碟、更名網卡或停用 IPv6）；X: 資料碟由 Nutanix Clone VM 建立。X: 不存在時預檢失敗，套件會以「Drive X: not found」失敗。舊請求 / 舊工作中的 setDisk 欄位會被忽略，不影響重試。
  • 已安裝偵測 (detect 規則)：在軟體主清單（REMOTE_INSTALL_SOFTWARE_MASTER / REMOTE_INSTALL_LINUX_SOFTWARE_MASTER）每一行最後可加上選填的 |@detect:類型:值；沒有此欄的行行為與過去完全相同。
    • Windows：名稱|NAS路徑|參數|@detect:reg:顯示名稱樣式[>=最低版本]，在 HKLM 的 Uninstall（64 位元與 WOW6432Node）以 PowerShell -like 比對 DisplayName（不分大小寫，可用 * ?；要子字串請寫 *Chrome*），可加 >=120.0 要求 DisplayVersion 不低於該版本； 或 @detect:file:C:\Program Files\App\app.exe（絕對路徑存在即視為已安裝）。參數欄為空時寫 名稱|路徑||@detect:...。
    • Linux：名稱|指令|@detect:rpm:套件名（rpm -q）、@detect:dpkg:套件名（dpkg-query，狀態須為 install ok installed）、@detect:cmd:指令（結束代碼 0 視為已安裝，指令內可含 |）。Linux 不支援最低版本。rpm / dpkg 查詢不使用 sudo；cmd 規則與安裝指令一樣經 sudo 執行，必須沒有副作用，且預檢不會執行 cmd 規則（預檢顯示「cmd rule not evaluated in pre-check」）。
    • 注意：Windows reg 只檢查 HKLM（64 位元與 WOW6432Node），每位使用者（HKCU）安裝的軟體不會被偵測；DisplayName 樣式中的 [ ] 視為一般字元，只有 * ? 是萬用字元；版本比較補齊為 4 段（1.2 等於 1.2.0）。偵測發生錯誤或超過 30 秒視為「未安裝」並繼續安裝（記錄警告），不會讓主機失敗。多個版本同時存在時以「, 」連接顯示。
    • 範例：Chrome|chrome\setup.msi|/qn|@detect:reg:Google Chrome*>=120.0、Agent|agent\a.exe||@detect:file:C:\Program Files\Agent\a.exe、ntp|yum install -y ntp|@detect:rpm:ntp。
    • 儲存格式：Settings 畫面把換行存成三個字元 \\n；解析時依欄位判斷（Windows 的路徑欄開頭 \\n 是 UNC 路徑如 \\nas01\soft，其餘位置為換行）。Linux 指令或規則中不可含反斜線加 n（儲存時會被拒絕）。
    • 規則會在儲存設定時驗證（未知類型、空值、版本格式、套件名稱含特殊字元、OS 不符皆會被拒絕）；所有值以 PowerShell 單引號字面值 / shell 引號傳遞，不會被當成程式碼執行。無效的規則在手動編輯設定檔時，執行與預檢會回 400。
    • 已安裝的套件結果為 { ok: true, skipped: true, exitCode: null, message: "Already installed (版本)" }，不複製、不安裝；工作選項 forceReinstall（畫面上的「Force reinstall」，預設關）可忽略所有規則。
  • 部署後清理：Windows 每個工作在客體上使用 X:\SOMP_Provision\<工作編號>\（每個套件一個編號子資料夾）；一台主機的套件處理完（成功或失敗）後，先把其中 install_*.log 的內容（每檔最後 1500 字、最多 5 檔）寫入工作記錄，再只刪除該工作資料夾（路徑必須位於 X:\SOMP_Provision 之下，不使用萬用字元；根資料夾僅在為空時才移除）。 腳本套件（.bat / .cmd / .ps1 所在資料夾）維持原本位置 X:\<資料夾名> 且不會被刪除（腳本可能安裝服務或排程並從該處執行），只有單一安裝檔（.exe / .msi）與其 install_*.log 放在工作資料夾並被清理；僅複製資料夾（無安裝檔）的套件屬於交付物，同樣不清理。安裝參數若把記錄寫到絕對路徑（例如 /l*v X:\x.log）不會被擷取或清理，請用相對路徑（安裝程式的工作目錄就是該套件資料夾）。每台主機開始時會順便清除 X:\SOMP_Provision 下超過 7 天、名稱符合工作編號格式且非本工作的殘留資料夾。清理失敗只在主機記錄顯示警告，不影響結果；選項 keepInstallers（「Keep installers」，預設關）保留資料夾並在記錄寫出位置。若工作逾時被強制終止，資料夾可能殘留。Linux 指令不會複製任何檔案，因此無需清理。
  • 通知 (Telegram)：每個工作最多三類訊息——開始的稽核訊息、各主機結果（合併批次訊息）、以及工作結束時一則「Provision」摘要（工作編號、操作者、BU、成功 / 失敗 / 需重開機數與前幾台失敗主機）。 摘要與其他安裝稽核紀錄受同一個「Remote Install」稽核開關控制。
  • 設定值 (環境設定 / Settings)：PROVISION_HOST_CONCURRENCY（預設 4，1–10）、PROVISION_HISTORY_RETENTION_DAYS（預設 180，30–730，過期工作每日清理）、 PROVISION_MIN_FREE_GB（預設 5，1–500，預檢 X: 最低剩餘空間；原本設為 0 的舊值執行時視為 1，儲存其他設定時只驗證本次有變更的欄位）。可在 Settings 的 Remote Install 分頁編輯（僅 SuperAdmin），儲存時伺服器端驗證範圍，不需重啟即生效。
  • 權限 (RBAC)：檢視工作與歷史需具 install 功能；執行、預檢、取消、重試、目標搜尋僅限 Operator 與 SuperAdmin；未知目標覆寫僅限 SuperAdmin。安裝參數（可能含授權碼）對 Viewer 以遮罩顯示。
  • 憑證安全：Windows 使用操作者登入的 AD 帳密、Linux 使用 LINUX_ADMIN_*，僅存在於記憶體 / 子行程環境變數，不會寫入資料庫、記錄、稽核或通知。

    • 30 秒一次性加密 Token：前端呼叫 POST /api/remote/token 經由 RBAC 驗證後，後端透過 AES-256-CBC 簽發包含連線參數的加密 Token，時效僅 30 秒，逾時自動失效。
    • WebSocket 專屬轉發通道：前端帶入 Token 連線至 /ws/remote?token={token}，Node.js 閘道驗證 Token 後以本機 TCP Socket (Port 4822) 轉發至 guacd。
    • 非致命錯誤安全遏止 (Crash Containment)：針對 Windows Server 2016 運維環境，後端對 WebSocket 異常中斷、網路斷線 (ECONNRESET, EPIPE) 與 guacd 逾時進行全域隔離，確保遠端桌面中斷絕不波及 Vanguard 主服務。
  3. Guacamole Server Daemon (guacd)：原生常駐守護行程，負責將 Guacamole 指令流與目標伺服器的 RDP (3389) 與 SSH (22) 協定進行高效解碼轉換。

🚫 排除主機（Excluded Hosts）

規則以環境、Tag 或 API Key 套用時，可讓少數主機完全不套用該規則。位置：Scout Monitor / Alerts & Rules / Agents 的規則頁籤，「🔗 Rule Assignments」下方的 🚫 Excluded Hosts 區塊（Operator / SuperAdmin 可新增與移除，Viewer 唯讀）。

  • 新增：Exclude host… → 選擇規則 → 依「Hosts」（可搜尋名稱 / IP / Tag、多選）或「Tag」（1–64 字元）排除 → 選填原因（最多 500 字）。
  • 完全不評估：被排除的主機不產生告警、不發通知、不記錄抑制、不計入抖動與升級；Agent 也不再收到該規則的監看目標與自我修復腳本。適用指標、離線 / 連線、Windows 事件與 Linux 日誌規則（含未綁定的全域日誌規則）。
  • 排除優先：即使主機另有直接綁定同一規則，仍以排除為準（新增時畫面警告）。
  • 既有告警：新增排除時、或主機之後才加上被排除的 Tag 時（畫面編輯或批次更新），該規則在這些主機上未處理的告警自動結束並標示 🚫 Excluded，不送「已恢復」通知；Worker 每分鐘另做一次檢查（含從其他途徑變更的 Tag），並保證被排除的組合不升級、不送維護結束補通知或抖動恢復通知。已排入 📦 告警摘要 的訊息仍會隨下一則摘要送出一次。
  • 離線規則：主機被排除其離線規則時不發離線告警，Dashboard 的離線判定改用預設門檻（5 分鐘或 3 倍回報間隔取大者）。同一主機適用多條離線 / 連線規則時，以最明確的綁定為準：直接指定主機 > API Key > Tag > 環境。
  • 可視性：每條規則列出被排除的主機 / Tag、原因、建立者與日期；主機明細的 Rules 分頁顯示「Excluded from: 規則名稱」；🔍 Preview Alerts 與 scripts\Alert_Preview.bat 同樣排除。
  • 清理與稽核：刪除規則會刪除其排除；刪除 Scout 主機或在 Server List 刪除主機時，一律刪除該主機的排除（Tag 排除保留）；每次新增 / 移除均寫入稽核。維護時段行為不變。

  • 35+ 模組動態 Feature Flags 熱開關： 可在不重啟系統的情況下動態啟用或關閉各功能模組（例如 dnsHub, adControl, serverList, serverCheck, remoteCmd, fortiProxy, squid, mail, elk, install, prometheus, nutanix, dataCenter, redisControl, inventory, ipam, sslMonitor, scheduler, netSearch, kubernetes, nasControl, workflow, sftpManager, database, networkDevice, monitorScout, monitorAlerts 等）。關閉時前端選單與後端 API 將同步隱藏保護。

🛡️ 內建「SuperAdmin」AD Mapping（SuperAdmin 功能開關）

  • 位置與性質：Settings → RBAC → AD Mappings 第一列，標示 Built-in。不綁定任何 OU / AD 群組（類型為 Role），套用於所有角色為 SuperAdmin 的使用者；永遠啟用。
  • 只能編輯、不能刪除：僅 SuperAdmin 可按 Edit 調整功能開關。刪除回 403、不可停用 / 改名 / 改類型或綁定目標，也不可建立同名（不分大小寫）Mapping；每次修改寫入稽核（開啟 / 關閉的功能清單）。

TROUBLESHOOTING & FAQ

故障排查與診斷中心

收錄在 Windows Server 2016+ 環境下運維 SOMP Vanguard 時可能遇到的常見問題、原因分析與標準處置步驟。

Scout Agent

1. Scout Agent Linux 部署報錯 (RPM should not be used directly... /bin/sh is needed)

現象說明：在 Ubuntu 或 Debian 主機上一鍵執行舊版 install.sh 安裝 Scout Agent 時，出現 rpm: RPM should not be used directly install RPM packages, use Alien instead! /bin/sh is needed 依賴性報錯。

根本原因：早期安裝腳本未區分 Linux 發行版家族，嘗試在 Debian 系上強制安裝 RHEL RPM 套件導致依賴性失敗。

標準處置步驟：

  1. 系統現已全面支援 DEB / RPM 雙發行版自動適配。
  2. 請至 Scout Monitor > Install Agent > Deploy Scout Agent 複製最新的一鍵指令。
  3. 最新版 install.sh 會自動偵測 Debian/Ubuntu 系統並下載 scout-*-amd64.deb 原生透過 dpkg -i 完成乾淨安裝，不再需要安裝 rpm 工具。
Scout Open API

2. Scout Open API 呼叫回傳 400 Bad Request (不支援的查詢參數)

現象說明：呼叫 Open API 端點（例如 /api/v1/open/logs/events?ips=192.0.2.6）時回傳 400 Bad Request，提示 不支援的查詢參數: ips (Unsupported query parameter(s))。

根本原因：Open API 全面啟用了嚴格參數白名單校驗，防止外部程式傳入錯誤或拼寫不一致的 Query 參數造成底層查詢漏洞。

標準處置步驟：

  1. 檢查傳入的參數名稱是否正確：主機 IP 查詢請使用 ?ip=192.0.2.6 或 ?host=192.0.2.6（不可使用 ips、server、node）。
  2. 受支援的參數清單可參考 API 回傳之 supportedParameters 或查閱 REST API 技術文檔。
CMDB 維運

3. CMDB 出現「⚠️ Drift Detected」硬體規格漂移告警

現象說明：主機卡片或表格列顯示 ⚠️ Drift Detected 警示標記。

根本原因：主機於虛擬化平台（如 Nutanix/vSphere）熱插拔擴充了 CPU 核心數或記憶體容量，導致即時遙測 (Live Specs) 與 CMDB 歷史記錄不一致。

標準處置步驟：

  1. 點擊主機開啟 360° CMDB Drawer。
  2. 檢閱 Hardware Drift Comparison Table 比對記錄值與實際值。
  3. 若擴充為正常合法變更，點擊 Sync Specs from Live Agent 按鈕，系統將自動校準 CMDB 資料並消除告警。
CMDB 同步

4. Server List (Simplified CMDB) 未自動顯示 Server Rack 中的既有 Compute 資源

現象說明：在 Server Rack 機櫃中配置的獨立伺服器或 Nutanix 刀鋒節點，改版後未出現在 Server List 清單中。

根本原因：Server List 尚未執行全域資料關聯同步。

標準處置步驟：

  1. 進入 Server Operation > Server List。
  2. 點擊右上角 Edit Mode 進入編輯模式。
  3. 點擊 Global Auto-Sync 按鈕。
  4. 系統將全量掃描所有 Data Center 的 Server Rack 結構，自動將所有 Compute 設備與 Nutanix 節點（包含 SN、iLO IP、CVM IP、位置槽位）匯入 CMDB。
登入認證

5. 本地管理員 (admin@local) 登入失敗 (Invalid credentials)

現象說明：輸入本地管理員密碼時顯示 "Invalid credentials"。

根本原因：LOCAL_ADMIN_PWD 在 .env 中被手動修改，且未正確套用 enc: 前綴或加密金鑰不符。

標準處置步驟：

  1. 進入伺服器後台目錄開啟 backend/.env。
  2. 將 LOCAL_ADMIN_PWD 暫時改回明文密碼（不含 enc: 前綴）。
  3. 重啟 somp-vanguard 服務後登入，再透過 Settings 介面儲存一次，讓系統自動重新套用 AES-256 加密。
機房架構

6. Data Centers 機房平面圖與現場實體方向相反

現象說明：點擊 2D Top-Down 平面圖時，機櫃編號由左至右或 U 數由上至下的順序與現場巡檢走道視角相反。

標準處置步驟：

  1. 進入 Data Centers 模組，點擊該機房卡片的 Edit 按鈕。
  2. 調整方向參數：
    • rackOrder: normal (由左至右) 或 reverse (由右至左)。
    • uOrder: normal (1U 在下/42U 在上) 或 reverse (1U 在上/42U 在下)。
    • rowOrder: normal 或 reverse。
  3. 儲存後所有機櫃將自動重新渲染並對齊現場視角。

K8s AI 診斷

8. Kubernetes AI 事故診斷執行時顯示「無法取得前次崩潰日誌」或分析逾時？

現象說明：在 Pod Logs 視窗執行「🤖 AI 診斷日誌」時，提示 previous terminated container not found 或外部 AI API 呼叫逾時。

根本原因：

  1. 若容器為首次啟動失敗（如 ImagePullBackOff）或尚未發生過重啟 (RestartCount = 0)，Kubernetes API 伺服器不存在 previous: true 的崩潰日誌，此屬預期正常行為。
  2. 若公司網路隔離阻斷對外部 OpenAI / DeepSeek API 的連線，外接 LLM 會觸發 8 秒逾時。

標準處置步驟：

  1. 系統已內建確定性離線專家規則引擎，當 external LLM 連線受阻時會自動平滑降級，針對 CrashLoopBackOff、OOMKilled Exit Code 137、ImagePullBackOff 等直接給出修復指令。
  2. 若需啟用外接 LLM，請進入 Settings > System Settings，配置正確的 HTTP Proxy 或企業內部私有 LLM 網址。
Mail Relay

9. Mail Relay 郵件發送遭拒 (550 5.7.1 Relaying denied / SPF fail) 排查？

現象說明：內部應用程式發送郵件時，Mail Relay 立即退信並拋出 550 5.7.1 Relay access denied 或 550 SPF check failed。

根本原因：發件端伺服器 IP 未加入 Postfix / Mail Relay 節點之 mynetworks 或 access 白名單，或發件網域的 DNS TXT (SPF) 紀錄未包含該 Mail Relay 出口 IP。

標準處置步驟：

  1. 進入 Service Platform > Mail Relay > Access List，確認發件伺服器 IP 是否已放行，修改後點擊 Deploy & Reload。
  2. 點擊退信紀錄右側的 [🤖 AI 診斷]，AI 會自動鑑定責任歸屬並給出具體的 SPF v=spf1 ip4:... ~all 設定語法。
SFTP 服務

10. SFTP 客戶端連線提示 Permission Denied 或無法列出目錄？

現象說明：FileZilla 或 WinSCP 使用 SFTP 帳號連線時認證失敗或提示 Fatal: unable to initialise SFTP: could not connect。

根本原因：Windows Server 2016 檔案系統 NTFS 權限未賦予 SOMP 服務執行帳號讀寫該 Chroot 資料夾之權限，或 SFTP 使用者密碼包含特殊不支援字元。

標準處置步驟：

  1. 進入 Service Platform > SFTP Manager，檢查該使用者狀態是否為 Active，以及 Chroot 路徑是否存在。
  2. 在 Windows Server 本機檢查目標目錄的 NTFS 安全性設定，確保 SYSTEM 及執行 somp-vanguard 的服務帳號具備「修改 (Modify)」權限。
多資料庫遷移

11. 系統切換至 PostgreSQL / MariaDB / MSSQL 後的啟動檢驗與雙庫串流遷移常見疑問？

標準升級切換流程 (SOP)：

  1. 設定連線參數：在 backend/.env 中配置 DB_TYPE=postgres（或 mariadb / mssql）及對應的 DB_HOST, DB_PORT, DB_USER, DB_PASSWORD, DB_NAME。
  2. 首次啟動自動建表：啟動後端服務一次，系統將於日誌輸出 [DB Manager] All database schemas and indexes ready.，確認核心資料表（包含 document_store）建立完畢後停止服務。
  3. 執行雙庫串流遷移腳本： 
    # 串流遷移 D:\somp-vanguard 下的 database.sqlite 與 scout.sqlite (可選 --days=7 僅遷熱資料)
node backend/scripts/migrate_all_sqlite_to_db.js --sqlite-dir="D:\somp-vanguard" --days=7
  4. 正式啟動服務：啟動 somp-vanguard 服務，此時登入系統即可見完整 CMDB 與歷史日誌，系統正式以目標關聯式資料庫全速運轉。

常見排查要點：

  • 若 .env 未配置任何 DB 參數，系統保證 100% 安全向下相容，維持原狀使用本地 SQLite，零業務中斷風險。
  • 遷移過程中若目標庫已有舊資料，腳本採用 UPSERT 與 INSERT OR IGNORE 策略，支援中斷後重複執行，保證不產生重複衝突主鍵。
Web 遠端桌面

12. Apache Guacamole Web-RDP / SSH 遠端連線提示 403 / 502 或連線畫面黑畫面排查？

現象說明：點擊 Web 控制台時出現 WebSocket connection failed (502 Bad Gateway)，或 RDP 桌面一直停留在黑畫面。

根本原因與標準處置步驟：

  1. 檢查 Guacamole Daemon (guacd) 狀態： 確認 guacd 服務（預設埠 4822）是否正在運行。若後端日誌出現 ECONNREFUSED 127.0.0.1:4822，請先於 Linux/容器端執行 systemctl status guacd 或 docker start guacd。
  2. 目標 Windows 主機 NLA (網路層驗證) 設定： 若遠端桌面停在黑畫面後斷開，通常為目標 Windows 伺服器啟用了強制 NLA 且憑證不符。請在後台連線設定中確認 security: any / rdp / tls / nla 設定，或在測試環境暫時放寬 NLA 進行交叉比對。
  3. 反向代理 (Nginx / IIS) WebSocket 轉發支援： 若前方有 Nginx 或 IIS 反向代理，必須開啟 Upgrade $http_upgrade 與 Connection "upgrade" Header，並將 proxy_read_timeout 調整至 3600 秒以上以防連線中斷。
