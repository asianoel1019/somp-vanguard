# license-issuer：SOMP Vanguard 授權簽發與管理網頁（本機）

在**保管簽章私鑰的那台電腦**上，用瀏覽器簽發 SOMP Vanguard 授權檔（`.lic`），並管理客戶、業務、續約、寄送、業績報表與備份的小程式。
命令列工具 `scripts\License_Issue.bat` 與本網頁共用 `scripts\licenseIssuerCore.js` 與同一個資料庫，規則一致。

* **只聽 127.0.0.1**（寫死在程式中），其他電腦無法連線；只有一位使用者（單一登入密碼）。業務與客戶是資料，不是登入帳號。
* **只供原廠使用，絕不部署**：`*license-issuer*` 已列在 `scripts\SCP_to_Prod.example.ps1` 與 `scripts\Deploy_to_Prod.ps1` 的排除清單。
* 必須放在 SOMP Vanguard 的原始碼資料夾中執行（會讀取 `backend\lib\licenseKeys.js` 的內建公鑰與 `backend\lib\licenseFormat.js` 的驗證規則）。
* 業務資料（業務、金額、訂單編號）只存在資料庫，**不會**簽入授權檔。

## 需求

* Node.js **22.13** 以上（使用內建的 `node:sqlite`，不需另外安裝資料庫）。版本太舊時程式會說明原因並結束。
* 以 `scripts\License_Keygen.bat` 產生的 Ed25519 私鑰，且其公鑰已內建於 `backend\lib\licenseKeys.js`（`KEY_ID` 對應）。
* 寄信功能（選用）需要一台可用的 SMTP 伺服器。

## 安裝與啟動

1. 執行 `Set_Password.bat`，輸入兩次登入密碼（至少 10 個字元，輸入時不顯示）。程式會以 `.env.example` 建立 `.env`，並寫入 `PASSWORD_HASH`（scrypt 雜湊，不存密碼本身）。
2. 編輯 `.env`，填入 `KEY_FILE` 等設定（見下方）。
3. 執行 `start.bat`：會先檢查 Node.js 版本（22.13 以上），第一次執行、或更新後套件清單（`package-lock.json`）有變動時自動安裝套件。看到 `Open http://127.0.0.1:8444/` 即啟動完成，用瀏覽器開啟該網址。
4. 第一次使用時，先到 **Settings** 新增業務（簽發時必填），並視需要調整方案（Plans）。

啟動前會檢查：`PASSWORD_HASH` 是否存在、私鑰是否可讀、私鑰是否與 `KEY_ID` 的內建公鑰相符（以私鑰簽一段測試資料、再以公鑰驗證），以及資料庫是否可開啟。任何一項不符都會顯示原因並結束，不會啟動。啟動訊息會列出授權檔資料夾、資料庫、登記表與寄信狀態。

要更換密碼時，再執行一次 `Set_Password.bat`，然後重新啟動。

## 設定（.env）

| 設定 | 說明 |
|---|---|
| `PORT` | 監聽埠，預設 8444（只在 127.0.0.1） |
| `KEY_FILE` | **必填**。私鑰檔，例如 `C:\somp-license-keys\k1-private.pem` |
| `KEY_ID` | 金鑰代號，預設 `k1`，必須是 `licenseKeys.js` 內建的代號 |
| `ISSUED_DIR` | 授權檔輸出資料夾，預設為私鑰旁的 `issued` 資料夾 |
| `DB_FILE` | 資料庫檔，預設為私鑰旁的 `license-issuer.db`，與 `License_Issue.bat` 共用 |
| `REGISTRY_FILE` | 由資料庫產生的唯讀登記表（Markdown），預設為私鑰旁的 `issued-licenses.md` |
| `PASSWORD_HASH` | 登入密碼的 scrypt 雜湊，請用 `Set_Password.bat` 產生，勿手動輸入 |
| `CONTACT_VENDOR` | 選填。Issue 表單 **Vendor** 欄位的預設值（最多 100 字） |
| `CONTACT_EMAIL` | 選填。Issue 表單 **Contact email** 欄位的預設值（最多 200 字，須為 `name@domain` 格式） |
| `SMTP_HOST` | 選填。SMTP 伺服器，例如 `smtp.example.test`；未設定時寄信功能關閉 |
| `SMTP_PORT` | SMTP 埠，預設 587 |
| `SMTP_SECURE` | `true`：一開始就使用 TLS（通常是 465 埠）；`false`（預設）：伺服器支援時使用 STARTTLS |
| `SMTP_USER` / `SMTP_PASS` | 伺服器需要登入時才填。`SMTP_PASS` 不會出現在畫面、API 回應或日誌中 |
| `MAIL_FROM` | 寄件者，例如 `SOMP License Issuer <license-issuer@example.test>`；未設定時寄信功能關閉 |
| `MAIL_ADMIN` | 選填。收件者（一個地址）：接收每週到期摘要的總表，也是測試信的預設收件者 |

* `CONTACT_VENDOR` / `CONTACT_EMAIL` 只是表單預設值，每張授權實際簽入的聯絡資訊以畫面上的兩個欄位為準。值不合規則時程式會顯示原因並拒絕啟動。
* 寄信設定缺少 `SMTP_HOST` 或 `MAIL_FROM`，或任何一項不合規則時，寄信功能關閉（Settings > Email 與啟動訊息會列出原因），其他功能照常可用。修改 `.env` 後需重新啟動。
* `.env`、`logs\`、資料庫（`*.db`）與備份檔不會進入版本控制；資料庫、備份與登記表預設都放在私鑰旁，不在原始碼資料夾中。

## 資料庫與登記表

* 所有資料（客戶、業務、方案、授權、事件紀錄、設定）存在 SQLite 資料庫 `DB_FILE`。每個多步驟的寫入都在交易中完成；簽發時若資料庫寫入失敗，剛寫出的 `.lic` 會被刪除，不會留下半套資料。
* `issued-licenses.md` 改為**由資料庫產生的唯讀副本**，每次變更後重新產生，第一行為 `<!-- Generated by license-issuer from license-issuer.db. Do not edit by hand. -->`。欄位：License ID | Customer | Type | Issued | Expires | Sales | Status | File | SHA-256 | Signed at。請勿手動編輯，手動加入的行不算資料。
* 為避免設定錯誤時覆蓋資料，程式不會覆寫「不是由資料庫產生、也未匯入過」的登記表，也不會覆寫由另一個資料庫產生的登記表（例如 `DB_FILE` 指錯檔案）；此時授權照常簽發並存入資料庫，畫面上方顯示登記表未更新的原因。
* **第一次啟動時的匯入**：資料庫是空的且已有舊版（手動維護的）`issued-licenses.md` 時，程式會：
  1. 先把舊登記表備份為 `issued-licenses.md.bak-YYYYMMDD-HHmmss`；
  2. 匯入每一行可讀的授權：以名稱建立客戶（大小寫不同視為同一客戶）、類型 Paid、業務與金額留空；沒有到期日的舊授權保留為 Format 1（無效）；
  3. 在啟動訊息中列出匯入數量，以及無法解讀而**未匯入**的行（含行號），請自行檢查。
  匯入只會做一次（之後不論網頁或命令列都不會再匯入）。若登記表已是產生的副本而資料庫是空的（例如 `DB_FILE` 設錯或資料庫遺失），程式會拒絕啟動，請改正設定或還原備份。

## 分頁說明

### Dashboard

* **This month / This quarter**：本月、本季簽發的授權數（Issued）、新簽（New）、續約（Renewal）、試用（Trial），以及各幣別的金額合計（不換匯）。已撤銷的授權不計入。
* **Renewals due**：可選 30 / 60 / 90 天內到期、尚未撤銷、且客戶還沒有更晚到期之付費授權的授權，列出客戶、業務與剩餘天數。按 **Renew** 會開啟 Issue 分頁並預填續約內容。
* **Trials**：有效的試用授權數、7 天內到期數，以及轉換率（曾試用且之後取得付費授權的客戶 ÷ 曾試用的客戶）。試用清單上的 **Convert** 同樣開啟預填好的 Issue 分頁。

### Issue

1. **Customer**：在搜尋框輸入名稱、email、統一編號或電話以篩選客戶並點選；新客戶按 **New customer**，直接在表單中填寫名稱（簽入授權的客戶名稱）與聯絡資料，簽發時一併建立。
2. **Plan**：選擇方案會自動填入到期日與金額（之後仍可修改）；Type（Paid / Trial）跟隨方案。不選方案時可自行選擇類型與日期。
3. **Sales person**：必填（試用授權也要）。客戶設有預設業務時會自動帶入。
4. **Amount / Currency / Order no.**：選填。金額 ≥ 0、最多兩位小數；幣別為 TWD、USD、EUR、JPY、CNY、HKD、SGD（預設值在 Settings 設定）。試用授權金額固定為 0。
5. **License ID / Issued / Expires**：預設為下一個可用編號、今天與方案期限；欄位下方顯示有效天數。
6. **Vendor / Contact email**：原廠聯絡資訊（選填，預設為 `.env` 的 `CONTACT_VENDOR` / `CONTACT_EMAIL`）。至少填一項時以 `contact: { vendor, email }` 簽入授權檔；產品會在付費功能鎖定畫面、到期提醒與到期通知顯示 `Contact <Vendor> (<email>) to renew.`。
7. 按 **Review** 會列出所有內容（含「新簽 / 續約 / 試用」判定）；確認後按 **Confirm & sign** 簽發。授權檔存為 `ISSUED_DIR\<ID>-<客戶名縮寫>.lic`（不會覆蓋既有檔案）。
8. 完成畫面可按 **Download .lic** 下載、**Send to customer** 寄給客戶（先預覽信件），或 **Open in Licenses** 查看。簽發後 Vendor / Contact email 保留在表單中，方便連續簽發。

從 Dashboard、Licenses 按 **Renew** 時，表單會預填同一客戶、同一業務、付費方案、今天為簽發日；原授權尚未到期時，新期間從原到期日的隔天開始（已到期、已撤銷或 Format 1 時從今天開始）。

### Licenses

* 篩選：客戶、業務（含未指派）、類型、狀態、簽發期間（本月 / 本季 / 本年 / 自訂日期）、是否顯示已撤銷，以及搜尋（編號、客戶、訂單編號）。
* 狀態：Revoked（已撤銷）> Format 1 (invalid)（舊格式，無效）> Expired（已到期）> Expires soon（付費 30 天內、試用 7 天內到期）> Active。
* 點選一筆開啟明細：所有欄位、檔案狀態、時間軸（簽發、下載、寄送、寄送失敗、重新提供、修改、撤銷、被取代、匯入）與以下動作：
  * **Renew**：開啟預填續約的 Issue 分頁。
  * **Edit**：只能修改業務、金額、幣別與訂單編號（時間軸記錄修改前後）。客戶與日期不能修改，請改用 Replace。
  * **Reissue**：把同一個檔案再提供給客戶（不重新簽章），需填寫原因；可選擇重新下載或以 email 寄出。
  * **Replace**：簽發一張新授權（同客戶、同類型與方案，新編號，日期、業務、金額可修改），並把舊授權標記為已撤銷（原因 replaced），兩張互相連結。**舊檔案無法收回，仍會有效到原到期日**，確認視窗會提醒。
  * **Revoke**：選擇原因（Terminated / Issued in error / Other）與備註。**撤銷只是紀錄**：授權離線驗證、無法收回，客戶手上的檔案仍會有效到原到期日，確認視窗會明確說明。已撤銷的授權不計入業績與續約清單。
  * **Send to customer**：預覽信件（收件者預設為客戶 email，可修改；主旨與內文來自範本；附件為 `.lic`）後寄出。已撤銷、已到期或 Format 1 的授權不能寄出。
  * **Download .lic**：下載授權檔（檔案的 SHA-256 前 12 碼必須與資料庫相符）。

### Customers

* 清單可搜尋，顯示聯絡人、email、預設業務、授權數與最近的到期日；**New customer** 新增客戶。
* 明細可修改名稱、email、聯絡人、電話、統一編號、地址、預設業務與備註，並列出該客戶的所有授權。改名只影響之後簽發的授權，已簽發的授權保留簽入時的名稱。
* **Issue a license** 開啟已選好此客戶的 Issue 分頁。
* **Delete customer** 只在客戶沒有任何授權時可用，刪除前會再次確認（無法復原）。

### Reports

* 期間（依簽發日）：包含指定日期的月 / 季 / 年、自訂起訖日或全部；可再依業務、類型、新簽 / 續約篩選。
* **Summary per sales person**：每位業務的授權數、新簽、續約、試用與各幣別金額（不換匯），最後一列為合計。已撤銷的授權一律不計入。
* **Detail**：逐筆列出；勾選 **Show revoked** 時也列出已撤銷的授權。
* **Export CSV**：匯出摘要或明細（UTF-8 含 BOM，Excel 可直接開啟；以 `=`、`+`、`-`、`@` 開頭的文字會加上 `'`，避免被當成公式）。

### Settings

* **Sales people**：新增、修改（名稱、email）、停用 / 啟用。停用的業務保留在既有授權上，但不能再被選用；有 email 的啟用中業務會收到每週到期摘要。
* **Plans**：新增、修改、停用 / 啟用方案（名稱、類型、期限〔月或天〕、價格〔可留空，簽發時再填〕、幣別）。預設方案：Trial 30 days、1 year、2 years、3 years。修改方案不影響已簽發的授權。
* **Email**：寄信狀態（SMTP 伺服器、寄件者、`MAIL_ADMIN`）、寄送測試信（收件者預設 `MAIL_ADMIN`，也可自行輸入）、客戶寄送信件的主旨與內文範本、每週摘要的星期與時間、預設幣別，以及 **Preview digest**（預覽本週摘要，不會寄出）。範本可用變數：`{customer}`、`{licenseId}`、`{issuedAt}`、`{expiresAt}`、`{type}`、`{vendor}`、`{vendorEmail}`、`{sales}`；拼錯的變數會原樣寄出並在儲存時提醒。
* **Backups**：按 **Create backup** 在資料庫旁建立 `license-issuer-backup-YYYYMMDD-HHmmss.db`（以 SQLite `VACUUM INTO` 產生一致的副本），清單中可下載各備份。

## 業務規則

* **新簽 / 續約**：從 Renew 簽發的付費授權（原授權為付費），或客戶先前已有未撤銷的付費授權時，記為續約；其他付費授權記為新簽。試用轉付費算新簽。Replace 產生的授權沿用舊授權的新簽 / 續約判定。
* **試用授權**：每位客戶最多一張（已撤銷的也算，但因 Replace 而撤銷的不算）、有效期最多 60 天（含簽發日與到期日）、金額 0；授權檔帶有 `trial: true`，產品顯示為 Trial，到期前 7、3、1 天提醒。
* **金額**：選填，≥ 0、最多兩位小數；報表依幣別分別加總，不換匯。
* **編號**：`L-YYYY-NNNN`，在資料庫中唯一（不分大小寫）。
* **日期**：必須真實存在；到期日不得早於今天或簽發日。

## 寄信與每週摘要

* **寄給客戶**：在 Issue 完成畫面或 Licenses 明細按 **Send to customer**，先預覽再寄出；寄出前會再次確認附件與資料庫中的 SHA-256 相符。成功或失敗（含錯誤訊息）都記錄在時間軸。
* **每週到期摘要**：程式執行期間每 10 分鐘檢查一次（啟動後約 5 秒先檢查一次）；到了 Settings 設定的星期與時間（預設星期一 09:00）且本 ISO 週尚未寄過時寄出：
  * 每位啟用中且有 email 的業務，收到自己負責、90 天內到期、未撤銷的授權（依到期日排序）；沒有到期授權的業務不寄。
  * `MAIL_ADMIN` 收到依業務分組（含未指派）的總表；沒有任何到期授權時也會收到一封「nothing expiring」的短信。
  * 寄送失敗會記錄在日誌，並在下一次檢查（至少間隔 10 分鐘）重試未寄出的部分；全部寄出後才標記本週已完成。錯過的星期只會在同一 ISO 週內補寄。
  * 只會寄到資料庫中的業務 email 與 `MAIL_ADMIN`。

## 備份與還原

* 在 **Settings > Backups** 建立備份（存於資料庫旁），並可下載到其他位置保存。建議定期把備份與私鑰分開、離線保存。
* 還原：關閉本程式 → 保留一份目前的 `license-issuer.db` → 將備份檔複製為 `DB_FILE` 指定的檔名 → 重新啟動。登記表會在下一次變更後依還原的資料重新產生。
* 第一次啟動匯入舊登記表前，程式會自動備份舊登記表（`issued-licenses.md.bak-YYYYMMDD-HHmmss`）。

## 命令列（scripts\License_Issue.bat）

命令列工具寫入同一個資料庫（第一次使用時同樣會匯入舊登記表），簽發後重新產生登記表。

```
scripts\License_Issue.bat --key C:\somp-license-keys\k1-private.pem --customer "Example Corp." --id L-2026-0001 ^
    --expires 2027-11-24 --out C:\somp-license-keys\issued\L-2026-0001-example-corp.lic ^
    --sales "Example Sales" --amount 12000 --currency TWD --order PO-2026-001
```

| 參數 | 說明 |
|---|---|
| `--key`、`--customer`、`--id`、`--expires`、`--out` | 必填：私鑰、客戶名稱（依名稱找客戶，不分大小寫；找不到時建立）、編號、到期日、輸出檔 |
| `--key-id` | 金鑰代號，預設 `k1` |
| `--issued` | 簽發日，預設今天 |
| `--registry` | 登記表檔，預設為私鑰旁的 `issued-licenses.md` |
| `--db` | 資料庫檔，預設為私鑰旁的 `license-issuer.db` |
| `--force` | 允許覆蓋已存在的 `--out` 檔案 |
| `--contact-vendor`、`--contact-email` | 選填，簽入授權的原廠聯絡資訊 |
| `--sales "<名稱>"` | 選填，必須是資料庫中啟用中的業務，否則結束（exit 1）；未提供時簽發後顯示警告 |
| `--amount <金額>` | 選填，≥ 0、最多兩位小數 |
| `--currency <幣別>` | 選填，TWD、USD、EUR、JPY、CNY、HKD、SGD |
| `--order <訂單編號>` | 選填，最多 100 字 |
| `--trial` | 簽發試用授權（每位客戶一張、最多 60 天、金額 0，授權檔帶 `trial: true`） |

* `--allow-duplicate-id` **已移除**：編號在資料庫中必須唯一，使用時會說明原因並結束（不寫入任何東西）。要更正已簽發的授權，請用網頁的 Replace。
* 結束代碼：0 成功；1 拒絕（未寫入任何東西）；2 已簽發並存入資料庫，但登記表副本未能重新產生（下次變更時會再產生）。

## 安全機制

* 只監聽 127.0.0.1；`Host` 標頭不是 `127.0.0.1:<埠>` 或 `localhost:<埠>` 的請求一律拒絕（防 DNS rebinding）。
* 密碼以 scrypt 雜湊比對（固定時間比較）；連續 5 次錯誤後鎖定 15 分鐘，畫面顯示剩餘次數與解鎖時間。
* 登入後的工作階段存在 HttpOnly、SameSite=Strict 的 cookie，閒置 30 分鐘自動登出；可隨時按 **Log out**。
* 所有 API 都需要登入；會變更資料的請求必須帶正確的 `Origin` 與綁定工作階段的 CSRF token。所有輸入都在伺服器端檢查，不合規則時回應原因且不寫入任何資料。
* 安全標頭：CSP（`default-src 'self'`，不使用外部 CDN、不使用內嵌 script / style）、`X-Frame-Options: DENY`、`Cache-Control: no-store`。
* 下載與寄送附件只限資料庫列出的 `.lic` 檔，且 SHA-256 前 12 碼必須相符；備份下載只限資料庫資料夾中的備份檔。不會送出私鑰或其他檔案。
* 寄信只用純文字、收件者須為單一有效地址，附件只來自資料庫列出的授權檔；`SMTP_PASS` 不會出現在畫面、回應、事件或日誌中。
* 稽核日誌 `logs\audit.log`（每行一筆 JSON）：登入、登出、簽發、取代、修改、撤銷、重新提供、下載、寄送、測試信、每週摘要、設定 / 業務 / 方案 / 客戶的變更、報表匯出與備份。不記錄密碼、雜湊、金鑰或 SMTP 密碼。
* 私鑰只在啟動時讀入記憶體，不會出現在畫面、回應或日誌中。
