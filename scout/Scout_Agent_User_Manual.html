Scout Agent 使用與設定手冊

Vanguard Agent-based 監控、日誌轉發與自癒維護終極指南

Windows Agent: v1.0.12 Linux Agent: v1.0.12

📖 系統簡介

Scout Agent 是部署於託管主機上的主動式監控代理程式。它定時採集硬體指標並回傳至 Vanguard 後端。 除此之外，它提供了強大的邊緣端自癒 (Self-Healing) 以及 日誌即時過濾並直推 ELK (Elasticsearch) 之功能，避免所有日誌皆透過 Vanguard 後端轉發而造成瓶頸。

📥 1. 安裝與升級

Agent 分為 Windows 執行檔及 Linux RPM 安裝包，伺服器背景排程會自動偵測對應路徑下的最高版號，並於前端提供一鍵更新。

1.1 目錄結構

請將更新的帶版號二進位檔案放置於 Vanguard 後端的主機對應路徑：

  • Windows 代理程式存放區：somp-vanguard\scout\scout-win\scout-win_v1.0.12.exe
  • Linux RPM 存放區：somp-vanguard\scout\scout-linux\scout-1.0.12-1.el10.x86_64.rpm

1.2 一鍵點檢與部署閘道 (Server Check Portal)

當您需要將新伺服器納入監控時，不需手動登入目標伺服器下指令安裝：

  1. 前往 Server Operations ➡️ Server Check。
  2. 在診斷設定中填入 IP（支援多行填寫），並填入 SSH 連線密碼。
  3. 點選「▶ Start Diagnostic」完成無代理的即時效能診斷。
  4. 診斷完畢後，針對未安裝 Agent 的主機點選 「Deploy Scout」，系統會在背景透過 SSH / WinRM 自動上傳並註冊最新版 Agent 服務。安裝完成後，狀態會立刻切換為 `⚡ Scout Active`。

🛡️ 2. 設定監控自癒 (Self-Healing)

自癒是指當監控指標 (如特定服務停止、記憶體耗盡) 觸發警報後，Agent 在邊端立即執行預設腳本進行重啟或清理。

⚠️ RBAC 權限管理要求

基於資安考量，新增/修改自癒指令碼屬於高敏感操作。使用者帳號必須在權限管理頁面配置 manage_self_healing 權限。 超級管理員 (SuperAdmin) 預設具備此權限，一般操作員 (Operator) 未授權時無法修改 any Remediation Script。

2.1 設定要素

  • Remediation Script (修復腳本)：當規則被判定為 Alert 狀態時，執行此區塊的指令。
  • Remediation Cooldown (冷卻時間)：執行一次修復後，在指定時間內（預設 300 秒）不再重複觸發執行，以給予服務重啟並恢復的時間。
  • Remediation Max Retries (最大重試)：在警報未解除狀態下，最多重試執行的次數。

💡 實用自癒 Script 範例

您可以直接複製以下範例到 Vanguard 控制台的 Remediation Script 輸入框中使用：

Linux Shell Script 
#!/bin/bash
# 偵測到 Nginx Offline 時的自癒處理
LOG_FILE="/var/log/scout_self_healing.log"
echo "[$(date '+%Y-%m-%d %H:%M:%S')] 偵測到 Nginx 服務異常，啟動修復程序..." >> $LOG_FILE

# 嘗試重啟 Nginx
systemctl restart nginx

# 檢驗重啟結果
if systemctl is-active --quiet nginx; then
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] Nginx 重啟成功！警報即將恢復。" >> $LOG_FILE
    exit 0
else
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] Nginx 重啟失敗，將等待下次重試。" >> $LOG_FILE
    exit 1
fi
Windows PowerShell Script 
# 偵測到 IIS AppPool 記憶體超載或回應異常時自動回收
Import-Module WebAdministration
$PoolName = "DefaultAppPool"
$LogPath = "C:\scout\self_healing_log.txt"

Add-Content -Path $LogPath -Value "[$(Get-Date)] 觸發 IIS AppPool ($PoolName) 回收程序..."

try {
    Restart-WebAppPool -Name $PoolName
    Add-Content -Path $LogPath -Value "[$(Get-Date)] AppPool $PoolName 回收成功。"
    exit 0
} catch {
    Add-Content -Path $LogPath -Value "[$(Get-Date)] AppPool 回收失敗: $_"
    exit 1
}
Linux Shell Script 
#!/bin/bash
# 當磁碟使用率過高時，自動清除舊的日誌與快取釋放空間
LOG_FILE="/var/log/scout_disk_healing.log"
echo "[$(date '+%Y-%m-%d %H:%M:%S')] 觸發磁碟滿載自癒，進行日誌清理作業..." >> $LOG_FILE

# 清除 nginx 30天以上的舊日誌
find /var/log/nginx/ -name "*.gz" -mtime +30 -exec rm -f {} \;

# 清除系統暫存檔與 yum / apt 快取
yum clean all || apt-get clean

# 重新評估空間
FREE_SPACE=$(df -h / | awk 'NR==2 {print $5}' | sed 's/%//')
echo "[$(date '+%Y-%m-%d %H:%M:%S')] 清理完成。目前根目錄空間使用率：$FREE_SPACE %" >> $LOG_FILE
exit 0

📊 3. 設定日誌推送至 ELK (Elasticsearch)

Scout Agent 支援將日誌資料在主機端即時過濾整理後，直接以 Bulk API 推送至指定的 Elasticsearch 叢集。

3.1 Windows 事件日誌轉發

在 Monitor Groups 的 Windows Event Policy 下，您可以設定 Index Name，並開啟 Elasticsearch Independent Mapping Policy (YAML) 欄位填寫映射結構。

3.2 Linux 特定日誌監控 (Log File Watchers)

在 Linux Log Subscription 下，開啟 Log File Watchers (Elasticsearch Push)，可動態監視多個文字日誌檔 (如 Nginx access log, secure log)，即時分析並轉發。

💡 日誌轉發 YAML 與設定範例

Windows Event Independent Mapping YAML 
# 啟用與設定 Windows 事件直推 Elasticsearch Policy
enabled: true
elasticsearch:
  hosts: 
    - "https://es-cluster.corp.local:9200"
  api_key: "V1dfMmJjM2RfNGU1Zl9nNmg3aThqOWs="
  ssl:
    verification_mode: "none" # 測試環境可略過 SSL 憑證校驗

# 欲擷取的 Windows 事件來源與層級
filters:
  channels:
    - name: "System"
      levels: ["critical", "error"]
    - name: "Application"
      levels: ["critical", "error", "warning"]

# 欄位映射轉換規則
mapping:
  event_time: "@timestamp"
  Computer: "host.name"
  EventID: "event.code"
  Message: "message"
  LevelDisplayName: "log.level"
Linux Log File Watcher Config 
# Linux Log Watchers - 監看日誌清單並直推 ES 範例
[
  {
    "path": "/var/log/nginx/access.log",
    "index": "nginx-access-prod-%{+YYYY.MM.dd}",
    "parser": "json",
    "fields": {
      "environment": "production",
      "service": "api-gateway"
    }
  },
  {
    "path": "/var/log/secure",
    "index": "os-auth-secure-logs",
    "parser": "regex",
    "pattern": "^(?<timestamp>\\b[A-Z][a-z]{2}\\s+\\d+\\s+\\d{2}:\\d{2}:\\d{2})\\s+(?<hostname>\\S+)\\s+sshd\\[(?<pid>\\d+)\\]:\\s+(?<message>.*)$",
    "fields": {
      "log_source": "syslog-secure"
    }
  }
]

🔒 4. 安全性與連線

  • 雙向 TLS：Agent 與後端 Vanguard 通訊支援 TLS 1.3 協定加密，預防資料包於傳輸途中被側聽或篡改。
  • 權限安全：自癒腳本由 Agent 本身以 OS 系統服務最高權限啟動執行，請務必嚴格控管能編輯自癒腳本的 Vanguard 帳號。
